What’s new in OneRingAI 1.1

A vendor-neutral execution layer, portable native Agents, Agent-aware Realtime, and safer long-lived sessions—without changing the connector-first Agent path.

Vendor-neutral Agent Runtime

Run native OneRingAI and Codex SDK agent systems through immutable specs, sessions, observable runs, capability preflight, explicit policy, workspaces, cancellation, and normalized results.

Portable distributed Agents

Export a resolved native Agent as data, hydrate it on a trusted desktop host, place tools locally or remotely, and verify executable compatibility with protocol-v2 fingerprints.

Agent-aware Realtime

Host-owned security

Portable package data never grants authority. Receiving hosts resolve connectors, identity, permissions, plugins, local implementations, provider policy, and every remote request from trusted state.

Current models and credentials

Registry v2 now covers 95 text/realtime models plus dedicated media registries. Runtime-only rotating OpenAI credentials support short-lived host keys across text and media requests.

New execution layer in 1.1

Run complete agents through one observable runtime

The Agent Runtime does not replace Agent.create() or rebuild native agent loops. It gives applications one lifecycle for configuring, running, observing, cancelling, and collecting results from complete OneRingAI and Codex SDK agents.

Native loops stay nativeDrivers adapt complete agent systems while preserving each system’s own execution loop and tool semantics.
Live event journalObserve messages, reasoning, plans, commands, file changes, usage, and terminal state with bounded replay.
Fail-closed capabilitiesModel, reasoning, structured output, images, workspace access, and policy are checked before native work starts.
Portable executionMove native Agents across trusted hosts and bridge browser-safe Realtime media without moving credentials or authority.

ONE OBSERVABLE RUN @everworker/oneringai/agent-runtime 
const codingAgent = runtime.agent({
  id: 'coding-agent',
  driver: 'openai.codex.sdk',
  connector: 'openai-main',
  model: 'gpt-5.6-terra',
  reasoning: { effort: 'high' },
});

const session = await codingAgent
  .openSession({
  context: { userId },
  policy,
  observation: {
    mode: 'live',
    detail: 'reasoning',
  },
});

const run = await session.run(task);
for await (const event of run.events()) {
  render(event);
}

const result = await run.result;

OneRingAI vs LangChain vs CrewAI vs OpenClaw

Feature Comparison — reviewed August 2026

OneRingAI is a unified TypeScript agent library (~165K source LOC, 23 direct runtime dependencies) with a connector-first native Agent path and an optional runtime for complete agent systems. Authentication, security, resilience, observability, multimodal inference, and distributed execution are first-class library concerns.

About OpenClaw: OpenClaw (~355K GitHub stars) is a self-hosted personal AI assistant platform for messaging channels (WhatsApp, Slack, Telegram, etc.), not a developer SDK. It is included here for architectural comparison, but serves a fundamentally different use case.

OneRingAI's advantage: A compact, single-package TypeScript surface keeps the common path at Connector → Agent → Provider. Runtime performance depends on the workload and provider, so benchmark your own use case rather than relying on framework-wide percentage claims.
